##### Task 1.1: DevOps 工具链搭建 (P0)

**目标**: 配置完整的代码质量和版本控制工具

**验收标准**:
- [ ] ESLint 配置完成且无新增错误
- [ ] Prettier 格式化统一
- [ ] Husky pre-commit hook 生效
- [ ] commit-msg lint 规范提交信息

**详细步骤**:

```bash
# 1. 安装开发依赖
pnpm add -D eslint prettier husky lint-staged @commitlint/cli @commitlint/config-conventional

# 2. 创建 ESLint 配置
# .eslintrc.js
{
  "extends": ["next/core-web-vitals", "prettier"],
  "rules": {
    "@typescript-eslint/no-unused-vars": "error",
    "@typescript-eslint/no-explicit-any": "warn",
    "prefer-const": "error"
  }
}

# 3. 创建 Prettier 配置
# .prettierrc
{
  "semi": true,
  "trailingComma": "es5",
  "singleQuote": true,
  "printWidth": 100,
  "tabWidth": 2
}

# 4. 配置 Husky
npx husky install
npx husky add .husky/pre-commit "npx lint-staged"
npx husky add .husky/commit-msg "npx commitlint --edit $1"

# 5. 配置 lint-staged
# package.json -> lintstaged config
{
  "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
  "*.{json,md}": ["prettier --write"]
}
```

**依赖关系**: 无前置依赖
**风险点**: 可能需要修复现有代码的 lint 错误
**预计工时**: 2 天

**完成标记**: ⬜ 待开始

##### Task 3.1: GitHub Actions CI/CD 流水线 (P1)

**目标**: 实现自动化构建、测试、部署流水线

**Pipeline 阶段**:

```yaml
# .github/workflows/ci-cd.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  # Stage 1: 代码质量检查
  lint-and-format:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm lint
      - run: pnpm format:check

  # Stage 2: 类型检查
  type-check:
    runs-on: ubuntu-latest
    needs: lint-and-format
    steps:
      - uses: actions/checkout@v4
      - run: pnpm install && pnpm tsc --noEmit

  # Stage 3: 单元测试
  unit-tests:
    runs-on: ubuntu-latest
    needs: type-check
    steps:
      - uses: actions/checkout@v4
      - run: pnpm install && pnpm test:run --coverage
      - uses: codecov/codecov-action@v3

  # Stage 4: E2E 测试
  e2e-tests:
    runs-on: ubuntu-latest
    needs: unit-tests
    steps:
      - uses: actions/checkout@v4
      - run: pnpm install && npx playwright install
      - run: pnpm test:e2e

  # Stage 5: 构建
  build:
    runs-on: ubuntu-latest
    needs: e2e-tests
    steps:
      - uses: actions/checkout@v4
      - run: pnpm install && pnpm build

  # Stage 6: 部署 (仅 main 分支)
  deploy:
    runs-on: ubuntu-latest
    needs: build
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Deploy to Vercel
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
```

**质量门禁规则**:
- 单元测试覆盖率 < 60% → ❌ 阻止合并
- TypeScript 错误数 > 10 → ⚠️ 警告但允许
- E2E 测试失败 → ❌ 阻止部署
- Lint 错误 → ❌ 阻止合并

**依赖关系**: Phase 2 完成
**预计工时**: 3 天

**监控指标仪表盘**:

```

├── Error Rate (错误率)
│   └── Target: < 0.1%
│
├── Performance (性能)
│   ├── LCP (Largest Contentful Paint) < 2.5s
│   ├── FID (First Input Delay) < 100ms
```

触发条件: M1-M4 任一里程碑延期超过 3 天

应对措施:
1. 召开紧急评审会议
2. 重新评估剩余任务优先级
3. 削减 Nice-to-have 功能
4. 申请额外资源或延长 Timeline

**Scenario B: 严重安全漏洞**

触发条件: 生产环境发现 Critical 漏洞

应对措施:
1. 立即启动 hotfix 分支
2. 2小时内修复并测试
3. 紧急发布 + 通知用户
4. 事后复盘 (Post-mortem)

**Scenario C: 第三方服务宕机**

触发条件: 核心 API 服务不可用 > 1小时

应对措施:
1. 启用降级模式 (关闭AI功能，保留基础UI)
2. 显示维护公告
3. 联系服务商
4. 评估备用方案

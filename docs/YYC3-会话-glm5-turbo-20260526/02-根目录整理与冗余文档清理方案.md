## 二、详细分析与整理方案

### 2.1 散落的源代码文件

#### 📄 customer-creation-form.tsx

**文件性质**: React组件（客户创建表单）
**当前行数**: 预估200+行
**功能描述**: 客户信息录入、AI分析、标签推荐

**问题**:
- ❌ 位于根目录，不符合Next.js项目结构规范
- ❌ 与customer-service模块高度相关但未整合
- ❌ 无法被其他页面通过路由引用

**建议方案**:

```bash
# 方案A: 移动到customer-service目录 (推荐)
mv customer-creation-form.tsx customer-service/customer-creation-form.tsx

# 更新导入路径（如果有引用）
# 从: import CustomerCreationForm from '@/customer-creation-form'
# 改为: import CustomerCreationForm from '@/customer-service/customer-creation-form'
```

**目标位置**: `/customer-service/customer-creation-form.tsx`

---

#### 📄 dashboard.tsx

**文件性质**: React组件（仪表板界面）
**当前行数**: 预估300+行
**功能描述**: 另一个版本的聊天/仪表板界面

**问题**:
- ❌ 与 `app/page.tsx` 功能高度重叠
- ❌ 可能是早期开发遗留的旧版本
- ❌ 造成维护混乱（不知道哪个是正式版本）

**决策流程**:

```
dashboard.tsx 是否被使用？
├─ 是 → 移动到 app/dashboard/page.tsx 或 pages/
│      并在README中说明用途
└─ 否 → 删除或归档
         └─ 归档位置: docs/archive/legacy-components/
```

**建议操作**:

```bash
# Step 1: 检查是否有其他文件引用此组件
grep -r "dashboard" --include="*.tsx" --include="*.ts" | grep -v "node_modules"

# Step 2a: 如果无引用，移动到归档目录
mkdir -p docs/archive/legacy-components
mv dashboard.tsx docs/archive/legacy-components/dashboard.tsx

# Step 2b: 如果有引用且确实需要，移动到正确位置
mkdir -p app/dashboard
mv dashboard.tsx app/dashboard/page.tsx
```

**风险评估**: 
- 如果删除：低风险（可能是废弃代码）
- 如果保留并移动：需更新所有导入路径

---

#### 📄 useSmartPrompt.ts

**文件性质**: Custom React Hook
**当前行数**: 预估100+行
**功能描述**: Prompt模板管理和智能填充

**问题**:
- ❌ 明显应该是hooks目录下的文件
- ❌ 已被设计为Hook模式（useSmartPrompt）
- ❌ 导入路径显示依赖 `@/config/prompt-templates`（该文件也不在正确位置）

**建议方案**:

```bash
# 移动Hook到正确位置
mv useSmartPrompt.ts hooks/useSmartPrompt.ts

# 同时处理其依赖的配置文件
mkdir -p config
mv prompt-templates.ts config/prompt-templates.ts
```

**目标位置**:
- Hook: `/hooks/useSmartPrompt.ts`
- 配置: `/config/prompt-templates.ts` 或 `/lib/config/prompt-templates.ts`

**需要更新的导入**:

```typescript
// useSmartPrompt.ts 内部
// 从:
import { ... } from '@/config/prompt-templates'
// 改为 (如果移到lib/config):
import { ... } from '@/lib/config/prompt-templates'
// 或保持不变 (如果在根目录创建config/)
```

### 2.2 样式文件重复问题

#### styles/globals.css vs app/globals.css

**检查步骤**:

```bash
# 对比两个文件差异
diff styles/globals.css app/globals.css

# 检查哪个被实际引用
grep -r "styles/globals.css" --include="*.tsx" --include="*.ts" --include=".mjs" --include=".js"
grep -r "globals.css" app/layout.tsx
```

**可能的场景**:

| 场景 | styles/globals.css 状态 | 建议 |
|------|------------------------|------|
| 完全相同 | 冗余副本 | 删除 styles/ 目录 |
| 部分不同 | 旧版本或特殊样式 | 合并到 app/globals.css，然后删除 |
| 完全不同 | 特殊用途样式 | 重命名为更具描述性的名称，如 `styles/legacy.css` |

**建议操作**:

```bash
# 如果确认可以安全删除
rm -rf styles/

# 或者先重命名备份
mv styles/ styles-backup-
# 测试几天后确认无影响再删除
```

## 三、执行计划

### 3.1 Phase 1: 分析确认 (Day 1)

**目标**: 确认每个散落文件的用途和依赖关系

```bash
# 创建分析脚本
cat > /tmp/analyze-root-files.sh << 'EOF'
#!/bin/bash

echo "=== 分析根目录散落文件 ==="
echo ""

files=(
  "customer-creation-form.tsx"
  "dashboard.tsx"
  "useSmartPrompt.ts"
  "system-architecture.ts"
  "prompt-templates.ts"
)

for file in "${files[@]}"; do
  if [ -f "$file" ]; then
    echo "📄 $file"
    echo "   大小: $(wc -l < "$file") 行"
    echo "   引用情况:"
    grep -r "$(basename "$file" .ts)" --include="*.tsx" --include="*.ts" 2>/dev/null | \
      grep -v node_modules | \
      head -5 || echo "     未找到引用"
    echo ""
  fi
done

echo "=== styles/ 目录分析 ==="
if [ -d "styles" ]; then
  echo "存在 styles/ 目录"
  ls -la styles/
else
  echo "styles/ 目录不存在"
fi
EOF

chmod +x /tmp/analyze-root-files.sh
/tmp/analyze-root-files.sh
```

**产出**: 文件依赖关系矩阵

## 五、自动化维护脚本 (可选)

### 5.1 根目录整洁度检查脚本

创建 `.husky/pre-push` 或单独的脚本 `scripts/check-root-cleanliness.sh`:

```bash
#!/bin/bash
# check-root-cleanliness.sh
# 检查根目录是否有多余的源代码文件

set -e

echo "🔍 检查根目录整洁度..."

# 允许在根目录的文件模式
ALLOWED_PATTERNS=(
  "*.config.*"
  "*.config"
  ".*"
  "*.md"
  "*.json"
  "*.lock"
  "*.yaml"
  "*.yml"
  "LICENSE*"
  "CHANGELOG*"
  "CODE_OF_CONDUCT*"
  "CONTRIBUTING*"
)

# 查找不允许的文件
DISALLOWED_FILES=$(find . -maxdepth 1 -type f \( -name "*.ts" -o -name "*.tsx" \) ! -name "vitest.config.ts")

if [ -n "$DISALLOWED_FILES" ]; then
  echo "❌ 发现不应存在于根目录的源文件:"
  echo "$DISALLOWED_FILES"
  echo ""
  echo "请将它们移动到合适的子目录:"
  echo "  - *.tsx → components/, app/, 或对应模块目录"
  echo "  - *.ts (hook) → hooks/"
  echo "  - *.ts (util) → lib/"
  echo "  - *.ts (type) → types/"
  exit 1
fi

echo "✅ 根目录整洁度检查通过"
exit 0
```

添加到package.json:

```json
{
  "scripts": {
    "check:clean": "bash scripts/check-root-cleanliness.sh"
  }
}
```

### 5.2 Git Hook集成

在 `.husky/pre-commit` 中添加：

```bash
# .husky/pre-commit (追加)
# 检查根目录整洁度
pnpm check:clean
```

## 六、风险评估与回滚

### 6.1 风险评估

| 操作 | 风险等级 | 可能的影响 | 缓解措施 |
|------|----------|------------|----------|
| **移动Hook文件** | 🟢 低 | 导入路径失效 | 使用git mv自动更新 |

| **移动组件** | 🟡 中 | 页面路由变化 | 更新导航和链接 |
| **删除dashboard.tsx** | 🟡 中 | 功能丢失 | 先归档不直接删 |
| **删除styles/** | 🟡 中 | 样式丢失 | 先备份对比差异 |

### 6.2 回滚方案

```bash
# 如果整理后出现问题，快速回滚
git checkout HEAD~1 -- .

# 或针对单个文件回滚
git checkout HEAD~1 -- customer-creation-form.tsx
# 然后手动移回原位
```

## 七、后续维护建议

### 7.1 建立文件放置规范

在 `docs/YYC3-团队通用-标准规范/YYC3-团队规范-开发标准.md` 中补充：

```markdown
## 文件放置规范

### 根目录
- 仅允许存放：配置文件、文档文件、许可证
- **禁止**存放：业务组件、工具函数、类型定义

### 各目录职责
- `components/` - 可复用的UI组件
- `app/` - Next.js页面和布局
- `hooks/` - 自定义React Hooks (必须以use开头)
- `lib/` - 工具函数和纯逻辑
- `types/` - TypeScript类型定义和接口
- `config/` - 应用配置和常量
- `[module-name]/` - 业务模块（如customer-service/）

### 新增文件时的Checklist
```
